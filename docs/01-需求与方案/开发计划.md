# Cockpit 电源控制与汉化开发计划

## 目标

在 Cockpit 主界面新增正式的“电源控制”Widget，通过远端 TCP Server 发送 Modbus RTU 指令帧控制 1～32 路电源，并通过寄存器读回确认实际状态。M3 通过后先完成简体中文国际化，再开展真实设备联调和电源控制稳定交付。

## 执行顺序

1. M0：迁移、建库与进度文件。
2. M1：开关按钮与状态原型。
3. M2：单通道 RTU-over-TCP 闭环。
4. M2.5：TCP Server 可配置原始 HEX 收发验证。
5. M3：多通道与设置页。
6. L1：汉化基础与核心界面。
7. L2：Cockpit 全界面汉化。
8. M4：真实设备联调。
9. M5：电源控制稳定交付。

每个里程碑必须完成测试、更新进度文件并交付用户人工确认。未获得确认时，不得开始下一里程碑。

## 通信边界

- 浏览器 Widget 不直接建立原始 TCP 连接。
- RTU-over-TCP 通信由 Electron/后端受控模块承担，界面通过类型化 IPC 调用。
- 写入动作不能直接改变“已开启/已关闭”状态，最终状态必须以寄存器读回值为准。
- 通信实现必须包含串行请求队列、超时、CRC16、拆包/粘包处理、异常码、重连和离线状态。

## 待确认协议资料

真实设备联调前需要获得：TCP Server 地址和端口、从站地址、各通道写入功能码与地址、开启/关闭值、状态寄存器功能码与地址、掩码、期望值和设备字节序说明。
