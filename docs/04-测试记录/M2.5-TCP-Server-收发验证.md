# M2.5 TCP Server 收发验证

范围：Cockpit 桌面版作为 TCP Client，连接用户启动的 SSCOM TCP Server。仅验证可配置地址、端口与原始 HEX 双向收发，不发送 Modbus 控制指令，不连接真实电源设备。

## 自动验证

- `yarn lint:fix`、类型检查、46 项自动测试和 Electron 生产构建通过。
- 临时 TCP Server 验证 Cockpit 发送的原始字节完整到达；服务端返回的字节以 TCP 数据块记录，不按 Modbus 帧解析。
- 覆盖不可用地址、服务端断开、非法 HEX、IPv4/主机名/IPv6 地址格式，以及对已连接目标执行“保存并应用”时先断开旧 socket 再连接新目标。
- 诊断 socket 独立于正式 Modbus 会话；关闭弹窗后会断开诊断 socket。

## 人工验收步骤

1. 在 SSCOM 创建 TCP Server，例如 `127.0.0.1:1600`。
2. 启动 Cockpit 桌面版，在“电源控制”Widget 标题栏点击连接测试图标。
3. 输入 SSCOM 地址和端口，点击“保存并应用”，确认状态变为“已连接”。
4. 输入 `01 03 00 00` 并发送，确认 SSCOM 完整收到相同 4 字节。
5. 在 SSCOM 发送 `AA 55 01`，确认日志显示接收、`3 字节` 和相同 HEX。
6. 点击“断开”后重新连接；关闭并重新打开 Cockpit，确认地址和端口仍被保留。
7. 将地址改为无效地址或关闭 SSCOM，确认界面显示错误且不会自动重连。
